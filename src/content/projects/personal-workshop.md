## 为什么做：想有一个自己的平台

最开始只是看到别人有自己的网站，也想自己试试。后来它成为发布内容的地方，现在又多了一个明确用途：在简历和项目展示中，让别人看到具体的项目过程和结果。

网站同时承担博客、工作台和项目展示。项目成果、开发记录与未完成的想法共同保留。

## 两次改版：先整理证据，再把作者放回来

旧站使用 Hugo 和 PaperMod，能够发布文章，但测试内容与泛化介绍占据主要位置，项目只剩链接。第一次用 Astro 重构时，我把项目职责、源码、发布入口和验证边界整理成结构化档案。

这次改版解决了信息缺失，却带来了新的问题：布局、颜色搭配和视觉焦点都像广告、宣传页面或公司大屏。项目很突出，作者反而不见了。

第二次改版保留 Astro 与项目证据，把首页改成方格纸上的个人工作台。首页直接呈现九术、近期更新、长文、碎片和正在制作的项目。

## 设计：个人感来自具体选择

页面使用方格纸、九宫格、墨迹批注和本地手写字体，让信息像放在一张正在使用的工作台上。小目录树用 SVG 表达，首屏保持轻量。

当前以“九”字印章作为识别。深浅主题、键盘焦点与减少动态效果设置属于基础可用性。

当前版本会随着真实写作和项目继续调整，设计记录也随每次改版保留。

## 实现：让内容模型先于页面数量

Astro Content Collections 分别管理项目、长文、碎片和现在页。统一内容函数把写作合并为时间流、搜索索引与 RSS；项目保留职责、状态、技术栈、源码和贡献说明。

搜索在浏览器本地运行，主题与筛选只做渐进增强。即使 JavaScript 没有执行，文章、项目、导航与旧链接跳转仍然可读。网站采用静态输出与 GitHub Pages，主要内容保存在 Markdown 中。

## 验证：排版问题也要有回归检查

验收包括构建、Astro 类型检查和浏览器回归。Playwright 覆盖桌面、平板和手机宽度，检查横向溢出、图片加载与实际宽高比、主题、搜索、筛选、键盘操作、RSS、旧链接和无 JavaScript 阅读。

图片拉伸问题正是一个具体例子：HTML 的原始宽高没有写错，CSS 却只给了宽度、没有覆盖固定高度。修复后，测试同时比较自然宽高比与渲染宽高比，检查同类排版问题。

## 与数据科学专业的联系

这个网站与数据科学专业的联系，在于把分散内容整理成有类型的数据，派生搜索、订阅和时间流，并用清晰结构帮助他人理解项目证据。

后续将增加真实数据分析与可视化写作，逐步展示数据处理、可视化和技术表达能力。
