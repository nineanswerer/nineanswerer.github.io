## 为什么做：想有一个自己的平台

最开始只是看到别人有自己的网站，也想自己试试。后来它成为发布内容的地方，现在又多了一个明确用途：在简历和项目展示中，让别人看到真实做过的东西，而不只是一行技术栈。

这个目的不等于把网站做成个人宣传页。它首先仍是我的博客和工作台，项目展示、开发记录与未完成的想法应该同时存在。

## 两次改版：先整理证据，再把作者放回来

旧站使用 Hugo 和 PaperMod，能够发布文章，但测试内容与泛化介绍占据主要位置，项目只剩链接。第一次用 Astro 重构时，我把项目职责、源码、发布入口和验证边界整理成结构化档案。

这次改版解决了信息缺失，却带来了新的问题：布局、颜色搭配和视觉焦点都像广告、宣传页面或公司大屏。项目很突出，作者反而不见了。

第二次改版保留 Astro 与项目证据，把首页改成方格纸上的个人工作台。九术、近期更新、长文、碎片和正在制作的项目共同出现，不再用一句大口号概括整个网站。

## 设计：个人感来自具体选择，而不是装饰

页面使用方格纸、九宫格、墨迹批注和本地手写字体，让信息像放在一张正在使用的工作台上。小目录树用 SVG 表达，不为了显得技术复杂而强迫首页加载 3D 场景。

没有真实头像时，以“九”字印章作为识别，不使用库存人物照片或虚构的 AI 人像。深浅主题、键盘焦点与减少动态效果设置则属于可用性，不是额外装饰。

现在的版本比上一版更接近个人网站，但我不认为设计已经完成。它仍需要随着真实写作和项目继续调整，而不是用“最终版”停止迭代。

## 实现：让内容模型先于页面数量

Astro Content Collections 分别管理项目、长文、碎片和现在页。统一内容函数把写作合并为时间流、搜索索引与 RSS；项目保留职责、状态、技术栈、源码和贡献说明。

搜索在浏览器本地运行，主题与筛选只做渐进增强。即使 JavaScript 没有执行，文章、项目、导航与旧链接跳转仍然可读。网站没有账号和服务端业务，因此继续使用静态输出与 GitHub Pages，不引入用不上的后台。

## 验证：排版问题也要有回归检查

验收不只检查构建是否成功。Astro 类型检查之外，Playwright 覆盖桌面、平板和手机宽度，检查横向溢出、图片加载与实际宽高比、主题、搜索、筛选、键盘操作、RSS、旧链接和无 JavaScript 阅读。

图片拉伸问题正是一个具体例子：HTML 的原始宽高没有写错，CSS 却只给了宽度、没有覆盖固定高度。修复后把自然宽高比与渲染宽高比加入测试，避免同类问题只靠肉眼再次发现。

## 与数据科学专业的关系：不硬贴“大数据”标签

这个网站本身不是分布式计算或机器学习项目。它与数据科学专业的联系，在于把分散内容整理成有类型的数据，派生搜索、订阅和时间流，并用清晰结构帮助他人理解项目证据。

后续更值得增加的是真实数据分析与可视化写作，而不是为了专业标签给首页堆图表。网站可以逐渐成为展示数据处理、可视化和技术表达能力的长期入口。

## 贡献与下一步

我负责产品方向、个人表达和关键设计取舍，AI 协作完成框架、组件、样式、测试与文字草稿。把这部分写清楚，是为了让项目经验可以被追问，也让自己知道下一步需要真正掌握什么。

接下来会继续补充有真实过程的项目与文章，改进个人信息和内容质量，并保持源码、测试与部署记录可核验。
