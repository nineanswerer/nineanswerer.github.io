## 为什么做：知道“满了”，却不知道空间去了哪里

Windows 能显示磁盘余量，却很难直接回答三个更具体的问题：哪一层目录真正占用空间、两次检查之间发生了什么、哪些内容可以相对安全地处理。普通列表在大目录下还会迅速失去可读性。

项目目标是把磁盘占用变成**可浏览、可比较、可回到文件操作的结构**。它面向个人电脑的普通目录分析，Minecraft 目录是开发中使用的真实样本之一。

## 能做什么：从扫描到维护的完整闭环

- **目录扫描与结构页**：呈现目录层级和空间占用，支持取消扫描、目录联接环检测和大目录逐层定位。
- **多种结构表达**：列表用于精确查找，空间分布用于比较占用，3D 树用层级和连线呈现目录关系。
- **快照与差异**：保存目录状态，比较新增、删除和大小变化，让后续变化有迹可循。
- **可复核清理**：参考目录与排除目录形成保留边界，执行前重新检查扫描基线，每组重复文件至少保留一份。
- **真实结果口径**：区分候选逻辑大小、待清空回收站大小与已核实分配空间释放，并将执行结果与基准快照比较。
- **故障恢复与诊断**：合并中断后先核对并恢复原路径；本地记录操作阶段，可主动导出经过路径脱敏的诊断文件。
- **更新检查**：手动查询 GitHub Release，并打开对应版本的发布页。

## 如何实现：本地遍历与多种视图分工

应用采用 Tauri 2 桌面架构：Rust 负责文件系统遍历、清理计划与本地操作，React 和 TypeScript 构建交互界面，Three.js 承担大目录的三维结构表达。

当前形态是**带 3D 可视化的可信磁盘分析与清理工具**。目录结构工作区包含三种视图，快照、差异、清理复核、诊断和更新使用独立工作流。视觉效果与交互命中分别设计，后端复核路径、保护与文件变化。

这里接近数据科学专业训练的部分，是保留原始事实、按任务聚合信息、说明样本与结论的边界，再选择人能理解的表达方式。

## 踩坑：文件系统包含环与变化

目录联接可能形成环，扫描也可能需要中途停止。实现中加入扫描取消、目录联接环检测，并拒绝路径逃逸与扫描根清理。分析后目录一旦新增内容，执行前复核会跳过整个变化目录。

回收站项目计入待清空大小。硬链接合并按独立实体的分配大小核实结果，无法完整读取时明确显示未知。执行后同步重算候选，已合并副本保持撤下状态。合并中断通过恢复记录处理，取消扫描保留可见的不完整结果。

## 验证：自动化、真实窗口与发布资产

在一个包含 **307,630 个文件、78.9 GB** 的真实目录上完成了扫描和结构展示验证。一次从启动扫描到结构页的自动化流程约 24 秒，包含固定等待，仅作为单次运行记录。

结项基线通过 **57 项 Rust 核心测试、8 项桌面测试和 20 项前端模型测试**，格式检查、Clippy、前端 lint/build 与 GitHub Actions 均通过。

真实窗口覆盖变化目录跳过、回收站结果、快照比较、硬链接合并和取消反馈。beta.1 → beta.2 覆盖升级保留 6 份快照且数据库哈希不变；卸载保留数据，重装可读取旧快照；免安装替换升级保留 1 份快照。诊断导出通过原生对话框生成 94 条事件，受检路径均脱敏。

10 万文件样本的静止 3D 树连续采集 120 帧，平均约 165.02 FPS，p95 与最大帧间隔均为 6.20 ms，长任务为 0。采样期间没有旋转或缩放操作，其他设备和高负载交互需要独立测量。

## 不足：验证范围仍有边界

清理操作仍需用户确认。当前构建尚未配置 Authenticode 签名；UAC、其他 Windows 设备和版本、不同文件系统、安全软件组合及真人外部测试尚未形成覆盖证据。Windows 回收站实际还原和回收站清空后的卷余量测量仍待完成。

## 版本：Beta 工程阶段已经结项

当前发布 **v0.3.0-beta.2**，属于 pre-release，提供 NSIS 安装包与免安装 ZIP。发布资产已从 GitHub Release 重新下载，文件名、字节数和 SHA-256 均与本地构建一致。公开仓库包含恢复开发所需的源码、锁文件、性能脚本、验收记录和交接文档。
