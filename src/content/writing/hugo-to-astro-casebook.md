## 旧网站的问题不在“看起来不够新”

旧站使用 Hugo 和 PaperMod，能够发布文章，也有搜索与目录。问题是测试文章和泛化介绍占据主要位置，项目只剩链接，访客很难知道我实际做过什么。

第一次重构选择了 Astro，把项目和文章拆成两个 Content Collection，为项目补上职责、状态、源码、发布入口和验证边界。网站从普通博客变成了可阅读的项目档案。

但改版后的首页又走向了另一端：大标题、代表案例和指标带太像产品官网。项目是证据，却不该取代作者和写作本身。

## 第二次改版，把“我”放回来

这次保留 Astro 和已有内容，新增碎片与现在页。首页不再从产品口号开始，而是先介绍九术、近期活动和最近写下的东西。

内容分为三种阅读尺度：

1. 长文保留完整的技术过程与验证边界；
2. 碎片记录一个具体决定或容易重犯的错误；
3. 项目页把职责、方案、证据和不足放在一起。

视觉也随之改变。方格纸、九宫格和墨迹批注代替统一的宣传卡片。小目录树只使用 SVG，不让首页再次成为三维应用的演示场。

## 内容模型先于视觉稿

项目包含职责、状态、技术栈、源码和发布入口；长文与碎片保留日期、摘要、标签和可选的关联项目。统一内容函数把两类写作合并成时间流、搜索索引与 RSS。

派生项目继续明确署名，独立项目则说明实际承担的工作。内容模型让贡献边界可以出现在每个相关页面，而不是藏在一段关于介绍里。

## 为什么继续使用静态 Astro

网站没有账号、数据库或服务端业务，主要内容是 Markdown 和少量交互。Astro 输出静态页面，适合 GitHub Pages，也允许在需要的地方加入少量客户端脚本。

主题切换、站内搜索、博客筛选和代码复制都是渐进增强。即使脚本没有执行，导航、项目与文章仍然可读；旧 Hugo 链接则使用静态跳转页，不依赖客户端路由。

## 本地字体与外部资源

正文使用系统中文字体，标题和短批注使用本地托管的 LXGW WenKai 子集。字体只包含本站实际出现的字符，并随文件保留 SIL Open Font License。

网站不依赖运行时第三方字体、库存人物照片或通用 AI 插画。没有真实头像时，用九字印章作为识别，而不是生成一个并不存在的人。

## 搜索与主题只做必要的客户端工作

搜索索引在构建时由项目、长文和碎片生成，以 JSON 嵌入搜索页。输入关键词后，浏览器在本地过滤并更新查询参数，不需要额外服务。

主题在页面头部尽早读取本地偏好，避免主体渲染后再闪烁切换。用户明确选择的主题写入 `localStorage`，未选择时跟随系统；同时尊重减少动态效果设置。

## 验证也要进入仓库

“本地看起来正常”不足以验收一个网站。构建前运行 Astro 类型检查，再使用本机 Edge 和 `playwright-core` 检查不同宽度、横向溢出、键盘交互、主题、搜索、订阅和旧链接。

测试脚本自己启动临时服务器，并在结束时关闭。截图用于检查真实排版，而不只是确认 HTTP 返回 200。

第一次改版还遇到过 TypeScript 7 与 `@astrojs/check` 的 peer 范围不兼容。解决方式不是使用 `--force` 跳过，而是将 TypeScript 固定在其支持的 6.x 范围。可复现性往往就藏在这些不显眼的选择里。
