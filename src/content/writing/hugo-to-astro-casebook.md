## 旧网站的问题不在“看起来不够新”

旧站使用 Hugo 和 PaperMod，能够发布文章，也有搜索与目录。真正的问题是内容结构：测试文章、重复教程和泛化介绍占据主要位置，项目则只剩链接。访客很难回答“做过什么、承担了什么、验证到哪里”。

因此，这次重构的目标不是更换一套热门皮肤，而是把网站从“按日期排列的博客”改成“以项目证据为中心的工程档案”。

## 内容模型先于视觉稿

新站将项目和文章拆成两个 Content Collection。项目包含职责、状态、技术栈、源码、发布入口和验证指标；文章则保留日期、摘要与标签。二者都能生成独立详情页，但不再共用一种卡片模板。

项目正文采用固定的问题意识，而不是固定文案：

1. 遇到了什么实际问题；
2. 为什么采用这个方案；
3. 有哪些关键取舍；
4. 已经做过哪些验证；
5. 还有什么不能被证明。

这种方式也让“派生项目”和“独立开发”可以被清楚区分。来源署名不是削弱项目，而是让个人贡献更可信。

## 为什么采用静态 Astro

网站没有账号、数据库或服务端业务，主要内容是 Markdown 和少量交互。Astro 默认输出静态页面，适合 GitHub Pages，也允许在需要的地方加入少量客户端脚本。

这次没有把整站做成客户端单页应用。主题切换、站内搜索和代码复制都是渐进增强：即使脚本没有执行，项目与文章仍然可读。

## 视觉：用层级代替装饰

视觉系统使用暖白、墨色和铁锈橙，深色模式则切换为炭灰。布局保留较明显的编辑式特征：大标题、细分隔线、非对称栏宽和紧凑的等宽元信息。

项目列表不是一列完全相同的卡片。标题、项目定位、简介和技术栈各有稳定层级；代表案例使用真实应用截图，其他项目则通过文本密度和间距建立差异。

另一个决定是不依赖在线字体和装饰性图片。这样减少外部请求，也避免视觉风格被素材库牵着走。

## 搜索与主题只做必要的客户端工作

搜索索引在构建时由项目和文章生成，以 JSON 嵌入搜索页。输入关键词后，浏览器在本地过滤并更新结果，不需要额外服务。

主题在页面头部尽早读取本地偏好，避免主体渲染后再闪烁切换。用户明确选择的主题写入 `localStorage`，未选择时跟随系统；同时尊重减少动态效果设置。

## 验证也要进入仓库

“本地看起来正常”不足以验收一个网站。构建前运行 Astro 类型检查，构建后使用本机 Edge 和 `playwright-core` 检查桌面与手机宽度、横向溢出、主题切换、搜索结果、详情链接和控制台错误。

测试脚本自己启动临时服务器，并在结束时关闭，避免交付后留下不可见的后台进程。截图用于检查真实排版，而不只是确认 HTTP 返回 200。

这次重构还遇到一个具体依赖问题：最新版 TypeScript 7 与当前 `@astrojs/check` 的 peer 范围不兼容。解决方式不是使用 `--force` 跳过，而是将 TypeScript 固定在其支持的 6.x 范围。工程可复现性往往就藏在这些不显眼的选择里。
